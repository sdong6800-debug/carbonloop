# CarbonLoop Rhino 模型翻译规则 V1.0

## 一句话

CarbonLoop 把 Rhino 模型自动翻译为“楼层 → 构件类型 → 材料类别 → 工程量 → 核对状态”，建筑师只确认不确定项，不重新录入模型。

## 为什么它不是一个单独的 AI Prompt

图层、对象属性、Rhino 材质和几何数量都是结构化数据，应先由确定性规则读取；只有名称含糊时才需要 AI 或人工判断。这样同一模型重复发送时结果稳定、可追溯，也不会让大模型编造材料。

## 输入来源与优先级

### 构件类型：它是什么

1. 对象自定义属性 `CarbonLoop.Type`（最高优先级）。
2. Rhino 对象名称。
3. 末级图层名称。
4. 完整图层路径。
5. 未命中时标为“待确认”。

### 材料：它由什么组成

1. 对象自定义属性 `CarbonLoop.Material`（最高优先级）。
2. 对象直接赋予的 Rhino Render Material。
3. 对象从图层继承的 Rhino Render Material。
4. 图层名称中的材料提示（低置信度，需确认）。
5. 未命中时标为“待确认”，不自动填造材料。

### 楼层：它属于哪里

1. 对象自定义属性 `CarbonLoop.Floor`。
2. 本次选择的楼层/图层范围。
3. 完整图层路径的第一段，仅作建议并允许修改。

### 工程量：有多少

1. 封闭 Brep、Mesh 或 Extrusion：读取 Rhino 净体积。
2. 非封闭几何：只读取包围盒供定位和预览，不把包围盒体积冒充工程量。

## 构件和材料必须分开

`Building::Floors::ext.Finish` 中的 `Floors` 表示构件是楼板；对象/图层材质 `Carrara marble` 表示材料是石材饰面。网页应显示“构件：楼板｜材料：饰面层/石材”，不能把楼板塞进“饰面材料”构件类别。

## 新建图层和修改材质的同步规则

1. 建筑师第一次运行 `CarbonLoopSend`，确定同步范围：选中构件、当前图层或整个模型。
2. 之后 Rhino 中新增/删除构件、修改对象名称、移动图层、重命名图层或更换对象/图层材质，插件延迟约 1.2 秒自动重新读取。
3. 网页每 2 秒检查一次最新版本并自动刷新，不需要再次点击发送。
4. 选择“整个模型”时，新建图层及其中的新对象会自动进入；选择“某层”时，仅该层及子层会更新；选择“部分构件”时，仅已选对象持续更新。

## 项目记忆与 AI 边界

- 明确名称（如 `Level 01::Slabs::Concrete`、`Concrete C30`、`Timber CLT`）由词典自动判断。
- 含糊名称（如 `Layer 01`、`Material 01`）无法可靠知道含义，网页要求建筑师确认一次。
- 确认结果按“完整图层＋原始材料＋牌号”保存在本机浏览器项目记忆中；同样的来源下次自动复用。
- 后续可让 AI 对未命中项提出候选，但 AI 只能给建议，不能静默覆盖模型事实。

## 推荐 Rhino 命名（非强制）

`楼层::构件::材料/用途`

示例：

- `Level 01::Slabs::Concrete`
- `Level 01::Columns::Steel`
- `Roof::Beams::Timber Glulam`
- `Building::Floors::ext.Finish`

即使不采用该格式，CarbonLoop 仍会读取 Rhino 已赋材质；规范命名只是提高自动识别率。
