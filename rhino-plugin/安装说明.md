# CarbonLoop Rhino 8 安装与演示

## 安装（老师或面试官）

1. 关闭旧版“启动 Rhino 连接”黑色窗口。
2. 从 GitHub 的 v0.3.1 Release 下载并解压 `CarbonLoop-Rhino-0.3.1-Windows.zip`，保持 `install-carbonloop.cmd` 与 `carbonloop-rhino-0.3.1-any-win.yak` 在同一目录，双击 `install-carbonloop.cmd`。看到 `Successfully installed carbonloop-rhino (0.3.1)` 才表示安装完成。这是预发布测试版；使用 Yak 安装，不使用旧版 `.rhi` 安装器。
3. 重启 Rhino 8。
4. 命令行输入 `CarbonLoop`。浏览器出现“Rhino 已连接”即安装成功。

## 第一次演示

1. 确认 Rhino 文件单位为 mm、cm 或 m。
2. 选中一个或多个构件。
3. 输入 `CarbonLoopSend`，在 Rhino 核验表中检查原始图层、材质和建议类别。
4. 明确匹配项可批量勾选；黄色行需逐组检查。拼写建议可用“填入本组拼写建议”填入，然后勾选“确认本组”。也可手动选择类型与材料，或明确保留未确定。
5. 修改“碳分析材料名”只改变本组对象的 CarbonLoop 属性，不改动共享渲染材质。修改图层名会影响同层全部对象，需勾选允许范围并统一同层各行的新名称。
6. 点“确认修改并发送”，网页显示结果并接收 Rhino 确认；未确定材料仍需补充。点击“关闭核验，不发送”不会发布模型。
7. 保存 `.3dm` 文件。来源不变的几何改动自动同步；新增对象或改图层、名称、材质后，命令行提示重新运行 `CarbonLoopSend` 确认。

## 可选：连接 DeepSeek

1. 安装 Node.js 20 或更高版本。
2. 解压 `CarbonLoop-AI-Connector-0.3.1.zip`。
3. 进入解压后的 `ai-service` 文件夹，双击 `connect-deepseek.cmd`，粘贴创建时保存的完整 API Key，选择模型并启用。
4. 配置窗口关闭后，已启动的服务仍可继续运行；要停止服务，在配置窗口点击“停止连接”或结束服务进程。密钥只保留在进程内存中，不写入网页或项目文件。
5. 回到网页勾选发送授权后，才能调用“结果解释”“修改影响”或“材料建议”。

## 为什么有时显示待核对

Rhino 的自由建模对象本身通常不知道自己是“梁、板、柱”。CarbonLoop 会按照对象属性、对象名、图层名和材料名逐级判断。无法可靠判断的对象会交给建筑师确认，这比强行猜测更适合真实项目。

推荐图层命名例子：

- `Level 01::Slabs::Concrete`
- `Level 01::Columns::Concrete`
- `Level 02::Beams::Structural Steel`
- `Facade::Glazing`
- `Facade::Mullions::Aluminium`

## 故障排查

- 页面显示未连接：在 Rhino 输入 `CarbonLoop`，看 Rhino 命令行的具体提示；网页会持续自动轮询。
- 安装完成不等于插件已加载：必须保存模型并退出旧的 Rhino 实例，然后重新打开 Rhino 8。旧进程不会热更新已加载的程序集。
- 提示端口被占用：插件会自动识别并复用兼容服务；如果服务由旧版 Rhino 提供，需保存文件并退出旧版后重新打开更新版 Rhino，网页才能使用新版资产。
- 换了另一个 Rhino 文件：再次运行 `CarbonLoopSend`；网页会用本次模型完整替换上一份模型，并要求重新核对，不会继续沿用旧构件数量。
- 新修改没有出现：检查命令行是否提示“待核验，已暂停发送”；运行 `CarbonLoopSend` 确认后继续。仅几何变化仍会自动同步。
- 大量对象待核对：先检查图层/对象名称是否带有构件含义，或在对象自定义属性中提供 `CarbonLoop.Type`。
